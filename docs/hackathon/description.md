# Vkin — The Meeting Copilot (Devpost project description)

**Track:** Best Apps and Agents
**Built with:** NVIDIA Nemotron (3.5 Lightning, 3 Ultra) on Nebius Token Factory · Deepgram Flux ·
Gemini (free tier, screenshots) · Electron · React + Vite · Supabase · Node.js

## Inspiration

Live conversations are where preparation goes missing. In an interview, a supervisor check-in or a client
call, you know the answer somewhere in your notes, last week's decisions or your own work history, but
you need it in the next five seconds, phrased the way you would say it. General chatbots don't help here:
they are too slow to consult mid-sentence, they forget what was agreed last time, and they will happily
invent a project you never did.

We wanted a copilot that is fast enough for a live call, remembers only what you choose to keep, and
refuses to make things up about you.

## What it does

Vkin is a Windows desktop copilot with a companion web dashboard.

- It listens to two channels, your microphone and the call audio, and detects when the other person has
  finished a question.
- It streams a short first-person answer into a private overlay, grounded only in your profile facts, the
  documents of the current **copilot**, and memory you approved in earlier sessions of the same **thread**.
- Small talk ("how are you?") gets a short natural reply without touching your profile.
- In a coding discussion you take one screenshot; Vkin answers with code that follows the constraints the
  interviewer said earlier, in order ("use Java", "only part two").
- **Deeper answer** regenerates the current answer with a larger model when you need more depth.
- At the end of a meeting Vkin drafts memory items (decisions, action items, commitments, open questions)
  from what was actually said. Nothing is used later until you approve it, and post-call notes are built
  only from approved items.
- The web dashboard lets you manage copilots, threads and memory, export everything, or delete your
  account, from a laptop or a phone.

## How we built it

- **Models.** Every answer is generated by NVIDIA Nemotron through Nebius Token Factory's
  OpenAI-compatible API, called with the standard `openai` SDK. **Nemotron-3.5-Lightning** is the default
  for live answers; **Nemotron-3-Ultra-550b-a55b** powers "Deeper answer". Thinking is switched off
  (`chat_template_kwargs.enable_thinking = false`) because a live answer has to start in well under a
  second. Qwen3-235B on the same platform is the fallback.
- **Choosing the default with data.** We ran a same-run benchmark on 23 grounded-answer questions:
  Lightning and Ultra were both 78% grounded before validation, but Lightning's first token arrived in
  295 ms (p50) versus 845 ms, at $0.0003 versus $0.0043 per answer. Lightning became the default, with
  Ultra one click away.
- **Grounding.** Retrieval assembles evidence (profile facts, copilot documents, approved memory) and the
  model must answer from it. An answer validator then checks every answer, code included, for restricted
  claims, forbidden categories (unapproved pay or work authorisation, contact details) and unsupported
  facts; it regenerates once or trims.
- **Cost safety.** A budget guard admits every billable call against a checksummed local ledger, reserving
  worst-case cost first; an unknown or stale price means no request is sent, and there is a hard stop.
  The hosted API applies its own per-provider spend caps before every upstream call.
- **Desktop.** Electron with renderer audio capture (plus an optional native WASAPI addon with Windows echo
  cancellation), Deepgram Flux for streaming speech-to-text with end-of-turn detection, an always-on-top
  overlay, and an audio watchdog that recovers stalled capture.
- **Accounts and memory.** Supabase Auth (email one-time code) and Postgres with row-level security forced
  on every table, composite owner foreign keys, revision checks and tombstones, so desktop and web sync
  without silent overwrites and one user can never read another's data.
- **Hosted service (in progress).** A Node API holds the provider keys, grants a 10-minute trial of
  active copilot time, bills it by database time through session leases, proxies Nemotron calls and
  relays Deepgram audio.

## Challenges we ran into

- **Latency versus quality.** A big model that answers in two seconds is useless in a live call. Turning
  thinking off and measuring Lightning against Ultra on the same questions settled it.
- **Making it refuse to invent.** The hardest bugs were answers that sounded right but borrowed a claim
  from the wrong project or added a number the evidence never had. The validator, and its tests, grew from
  those cases.
- **Turning a single-user tool into a product.** Vkin started as a copilot built for one person. Removing
  every hardcoded assumption about that person, while keeping the protections they relied on, touched the
  prompts, the validator, the packaged defaults and the tests.
- **Sync without data loss.** Desktop and web edit the same rows. Client UUIDs, revision numbers checked
  by a database trigger, tombstones, and "delete wins" rules replaced last-write-wins.

## Accomplishments that we're proud of

- A measured, defensible model choice instead of a guess, at about 14× lower cost per answer.
- Memory that is opt-in by design: drafts from real speech only, used only after approval, and isolated
  per copilot and per user by the database itself.
- Hundreds of automated desktop tests plus web and server tests, all running with mocked providers, and
  two independent review cycles whose findings were fixed with regression tests.
- Small talk, coding questions and personal questions each take a different, appropriate path.

## What we learned

- Reasoning models need their thinking explicitly disabled for real-time use, and the parameter is
  model-specific.
- Grounding is a system property, not a prompt property: retrieval, a validator and tests together do
  what no single prompt does.
- Spend limits belong in code that runs before the request, with "unknown price means no request".
