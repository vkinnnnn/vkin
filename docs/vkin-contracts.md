# Vkin shared contracts (v1, 2026-10-28)

Owner: main agent. Workers must not change this file; propose changes in their report.

## Hierarchy

Account (Supabase auth user) → Profile → Copilot (workspace) → Thread → Session → Memory items / transcript lines.

- A **copilot** is a context configuration: purpose, instructions, documents, answer preferences, restricted
  claims, memory scope, keyterms. It is never a fine-tuned model.
- A **thread** is an ongoing relationship across sessions (one supervisor, one company's interviews).
- A **session** is one meeting.

## Identity and sync rules (all records)

- `id` is a UUID v4 generated by the client. Writes are idempotent upserts on `id`.
- `user_id` defaults to `auth.uid()` on the server.
  - The **web** never sends it.
  - The **desktop** sync sends its store's account id as defence in depth: if the signed-in session changed
    mid-sync, RLS `WITH CHECK` rejects the row (42501) instead of filing it under the new user.
  - The server never trusts any client-sent owner: RLS enforces `user_id = auth.uid()` on every write.
- Server errors:
  - `PT409 vkin_rev_conflict`
  - `PT410 vkin_tombstoned`
  - `PT403 vkin_transcript_disabled`
  - `PT400 vkin_parent_immutable` (parent links cannot change)
- RPC parameter names: `vkin_delete_thread(p_id uuid)` and `vkin_delete_account_data()`.
- `rev` is an integer starting at 1. An update must send `rev = stored_rev + 1`, or the server rejects it
  with a conflict (trigger `vkin_check_rev`). There is no silent last-write-wins.
- `updated_at` is a server timestamp (trigger), used as the pull cursor.
- `deleted_at` is a tombstone. Deleted rows stay as tombstones so other devices learn of the delete.
  Content columns are cleared on delete (`text = ''`, `title = ''`).
- Child rows carry `(parent_id, user_id)` composite foreign keys to the parent's `(id, user_id)`, so a child
  can never point at another user's parent.

## Tables (Postgres, schema `public`, all with RLS: `user_id = auth.uid()` for every operation)

| table | columns (besides id, user_id, rev, created_at, updated_at, deleted_at) |
|---|---|
| `profiles` (id = user_id) | `display_name text`, `about text` (≤ 20k), `today_context text` (≤ 2k, private, optional), `settings jsonb` (`save_transcripts_default bool`, `memory_enabled bool`) |
| `profile_facts` | `text` (≤ 2k), `shareable bool default false` (usable by all copilots only when true), `source text` |
| `copilots` | `name` (≤ 120), `purpose` (≤ 2k), `instructions` (≤ 20k), `answer_prefs jsonb`, `restricted_claims text[]`, `memory_scope text check in ('thread','copilot')` default `'thread'`, `use_profile_facts bool default true`, `keyterms text[]` |
| `documents` | `copilot_id` FK, `title`, `kind text check in ('about_me','about_them','notes','other')`, `storage_path text` (bucket `documents`, path `<user_id>/<copilot_id>/<id>`), `chars int`, `approved bool default false` |
| `threads` | `copilot_id` FK, `title` (≤ 200), `status text check in ('active','archived')` |
| `sessions` | `copilot_id`, `thread_id` FK, `started_at`, `ended_at`, `save_transcript bool default false`, `summary text` (≤ 8k, approved summary only) |
| `memory_items` | `copilot_id`, `thread_id`, `session_id` (nullable), `kind text check in ('topic','decision','open_question','action_item','commitment','fact')`, `text` (≤ 2k), `status text check in ('draft','approved','forgotten')`, `origin text check in ('my_speech','their_speech','confirmed','note')`, `source_at timestamptz`, `due_at timestamptz` |
| `transcript_lines` | `session_id` FK, `speaker text check in ('me','them')`, `text`, `at timestamptz`. Written only when the session's `save_transcript` is true. |

Rules:

- Only `status='approved'` memory is ever retrieved for answers. Drafts are shown for editing only.
- `origin` records where a memory item came from. A suggestion the copilot generated is never
  `my_speech`. `commitment` items require `origin in ('my_speech','confirmed')`.
- Forget = `status='forgotten'`, `text=''`, `deleted_at=now()`. The local retrieval index drops the item, and
  any session `summary` that cited it is regenerated or cleared.
- Deleting a thread tombstones its sessions, memory items and transcript lines (server function
  `vkin_delete_thread(id)`, security invoker).
- Export: the client reads all the user's rows and writes JSON. No server-side export store.

`copilots.answer_prefs` keys (shared by web and desktop):
- `length`: short | balanced | detailed
- `tone`: conversational | professional | formal
- `star`: auto | manual | off
- `filler`: none | subtle
- `technical_depth`: light | medium | deep
- `format`: prose | bullets

Defaults: balanced, conversational, auto, subtle, medium, prose.

## Storage

- Bucket `documents` is private.
- Policy: the object path's first segment must equal `auth.uid()`.
- Signed URLs expire in 60 s and are never cached across accounts.

## Desktop local store (`src/main/vkin/store.js`)

- Path: `<dataRoot>/vkin/<account>/vkin.json`. `<account>` is `local` before sign-in, otherwise the Supabase
  user id.
- Atomic write (tmp + rename) and `schemaVersion: 1`.
- Same record shapes as above, plus `dirty: true` for unsynced rows and a pull `cursor` per table.

API (all sync, return plain objects; throw `VkinError {code}` on validation failure):
- `createCopilot(fields)`, `updateCopilot(id, patch)`, `deleteCopilot(id)`, `listCopilots()`
- `createThread(copilotId, title)`, `listThreads(copilotId)`, `deleteThread(id)`
- `startSession(threadId, {saveTranscript})`, `endSession(id)`, `listSessions(threadId)`
- `addMemoryDraft(sessionId, items[])`, `updateMemory(id, patch)`, `approveMemory(ids[])`, `forgetMemory(id)`
- `approvedMemory({copilotId, threadId, limit})`: the retrieval input. It respects `memory_scope`: thread scope
  returns only that thread's items; copilot scope returns all threads of that copilot. It never crosses
  copilots.
- `profile()`, `updateProfile(patch)`, `listFacts()`, `addFact()`, `forgetFact(id)`
- `exportAll()`, `wipeAccount()` (sign-out clears private device state)

## Answer engine inputs (runtime worker)

`engine.build({ ..., vkin: { copilot, threadMemory: [{id,kind,text,source_at}], profileFacts: [{id,text}], todayContext } })`

- Memory evidence ids are `MEM-<id>` and fact ids `FACT-<id>`; both count as validator support.
- Small talk (`greeting`, `small_talk`, `rapport`) uses **no** profile, pack or memory evidence. Only
  `todayContext` is allowed, and only when non-empty.

## IPC (desktop, main ↔ prep window)

`prep:cmd` gains `vkin.*` commands, all through `ipcMain.handle`, with the sender checked by `trust.js`:
- `vkin.copilots.list|create|update|delete`
- `vkin.threads.list|create|delete`
- `vkin.sessions.list`
- `vkin.memory.list|update|approve|forget`
- `vkin.select { copilotId, threadId|null }` sets the active copilot and thread; `null` means start a new thread
- `vkin.active` returns `{ copilot, thread }`, the selection used by the next meeting
- `vkin.local.list` lists the copilots created before sign-in
- `vkin.adoptLocal { copilotIds|null, removeFromLocal }` copies them into the signed-in account; it is
  idempotent and only runs on user request (`store.adoptFrom`, `store.purgeLocal`)
- `vkin.profile.get|update`
- `vkin.export`, `vkin.auth.status|signIn|verify|signOut`, `vkin.sync.now`
